EXPORT COMPLIANCE (App Store Connect submission questions + Info.plist key ITSAppUsesNonExemptEncryption)

THE OWNER MUST CONFIRM THIS. I am not a lawyer and this is not legal advice. Apple states: "it's your responsibility to review the Export Administration Regulation ... you're responsible for all liabilities associated with misinterpretation of export regulations or claiming exemption inaccurately" (App Store Connect Help, "Overview of export compliance", read 2026-10-11).

WHAT THE APP ACTUALLY USES
1. Encryption provided by macOS: HTTPS/TLS through URLSession (playlist and Xtream requests, logos and posters, downloads, the direct build's update check). Apple's page (developer.apple.com/documentation/security/complying-with-encryption-export-regulations, read 2026-10-11): "Typically, the use of encryption that's built into the operating system - for example, when your app makes HTTPS connections using URLSession - is exempt from export documentation upload requirements".
2. Encryption that is NOT the operating system's: the bundled libmpv/FFmpeg (scripts/make-app.sh: media-kit libmpv-darwin-build v0.7.3) contains mbedTLS, which opens https:// streams and HLS key and segment requests (player option tls-verify=yes with /etc/ssl/cert.pem, Sources/IPTVPlayer/PlayerOptions.swift), and FFmpeg's own AES code, which decrypts standard HLS AES-128 segments. The media-kit release lists Mbedtls and Mbedcrypto frameworks (its README, read 2026-10-11). This is standard TLS and standard AES; nothing proprietary or unpublished.
3. No encryption of user data by the app itself: passwords sit in the local database in plain text with file permissions 0600 (Sources/IPTVCore/SecretStore.swift), backups are plain JSON. The release signature check uses CryptoKit (Sources/IPTVCore/ReleaseSignature.swift, direct-build updater only; keep it out of the App Store build with the rest of the updater).
4. Plain http:// sources are allowed (NSAllowsArbitraryLoads), so some traffic is not encrypted at all.

APPLE'S RULE FOR THE INFO.PLIST KEY (same Apple page)
"Set the value to NO if your app - including any third-party libraries it links against - doesn't use encryption, or if it only uses forms of encryption that are exempt from export compliance documentation requirements. Otherwise, set it to YES."
Point 1 alone would be exempt. Point 2 is the part to decide, because the standard-algorithm library is not the operating system's. So the planned ITSAppUsesNonExemptEncryption = NO is only right if point 2 also falls in an exemption.

WHICH EXEMPTION COULD COVER POINT 2 (from my memory of U.S. Export Administration Regulations, Category 5 Part 2; the questions in App Store Connect are the authority, read them in the dialog)
- The "primary function" decontrol (formerly Note 4): not controlled if the item's primary function is not information security, a computer, sending/receiving/storing information (except in support of entertainment, mass commercial broadcasts, digital rights management or medical records management) or networking, AND the cryptography is limited to supporting that primary function. A media player whose TLS and AES only carry the stream the user asked to play is the typical example, and "entertainment" is named in the carve-out.
- The "limited to authentication, digital signature, or decryption of data/files" exemption: covers FFmpeg's decryption of HLS segments, but not TLS as a communications protocol by itself.
- "Mass market" encryption under License Exception ENC (740.17(b)(1)) is NOT an exemption from reporting: Apple's note says an app using exempt forms "might alternatively be required to submit a year-end self-classification report to the U.S. government".
Decide with a lawyer or with the BIS text, not with this file.

WHAT TO DO (pick one; I recommend the first, then confirm)
A. Walk through the App Store Connect export-compliance questions truthfully: "uses encryption" yes; proprietary or non-standard algorithms: no; standard algorithms instead of or in addition to the OS: yes (mbedTLS, AES in FFmpeg). Then answer the exemption question according to the primary-function reasoning above only if you agree with it. If the dialog then says no documentation is needed, set ITSAppUsesNonExemptEncryption = NO in the Mac App Store Info.plist and keep a note in the repository of why. Put the year-end self-classification report on a calendar if your lawyer says it applies.
B. If you are not comfortable asserting the exemption: answer so that documentation is requested, upload what App Store Connect asks for (it is usually a self-classification or CCATS), and set ITSAppUsesNonExemptEncryption = YES with ITSEncryptionExportComplianceCode when Apple gives you the code. Review takes about two business days per Apple's page.
C. Never answer NO "to make the question go away". The question comes back on every build otherwise, and a wrong claim is the owner's liability.

FRANCE: Apple's page says encryption apps distributed in France are controlled by the French authority (main items: secure storage, secure communications, anti-virus; exemptions: banking and medical). A media player is none of those items, but App Store Connect may ask about France: answer it from the same reasoning and keep it consistent.
