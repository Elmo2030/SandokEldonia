APPLE'S DEFINITIONS (developer.apple.com/app-store/app-privacy-details and App Store Connect Help "Overview of app privacy", read 2026-10-11)
- "Collect" refers to transmitting data off the device in a way that allows you and/or your third-party partners to access it for a period longer than what is necessary to service the transmitted request in real time.
- "Third-party partners" refers to analytics tools, advertising networks, third-party SDKs, or other external vendors whose code you've added to your app.
- If data is "sent to your servers then immediately discarded after servicing the request, you do not need to disclose" it.

WHY "NOT COLLECTED" IS TRUE (each point checked in the code, files from the repository root)
1. The developer receives nothing. There is no developer server, endpoint, account, token or API key anywhere in Sources/ (grep for URLSession, URLRequest and every http(s) literal: the only fixed addresses are github.com and api.github.com in Sources/IPTVCore/Updater.swift, and youtube.com/watch in Sources/IPTVCore/ItemInfo.swift, which is built for the user's browser, see 3 and 4).
2. No analytics, advertising, crash-reporting or tracking SDK. Package.swift has one dependency, GRDB.swift (a local SQLite library). The bundled libmpv/FFmpeg (scripts/make-app.sh) play media and do not report anything. grep for analytics, telemetry, tracking, crashlytics, sentry, firebase, mixpanel, amplitude finds nothing in Sources/.
3. Every request the app makes goes to a server the USER typed in or that the user's source returned: playlist, Xtream API, program guide, title details, logos and posters, streams and downloads (Sources/IPTVCore/XtreamClient.swift, SyncService.swift, Sources/IPTVMac/Downloads.swift, OnboardingView.swift). The user's IPTV provider is not the developer's "third-party partner": no code of theirs is in the app, the developer chose none of them, and the app talks to them only because the user told it to, like a browser or an FTP client. This reading is the owner's to confirm; if App Review disagrees, the data types that would then be "collected" are only those in the requests below, none "linked to the user's identity" by the developer.
4. The Trailer button opens an https://www.youtube.com/watch?v=... address in the user's default browser (NSWorkspace.shared.open, Sources/IPTVMac/AppModel+Data.swift): the app sends nothing to YouTube.
5. Everything the app stores stays on the Mac: sources, lists, favorites, watch history, settings, cached images (Sources/IPTVCore/AppDatabase.swift, UserData.swift, UserDefaults). Backups are written only when the user exports them (Backup.swift). On-device data is not "collected".
6. The update check (Updater.swift, AppModel.swift "updateLoop") exists only in the direct-download build. It is NOT allowed in the App Store build anyway (Guideline 2.4.5 (vii): "They must use the Mac App Store to distribute updates; other update mechanisms are not allowed"). The App Store build must not contain it: see CHECKLIST.md, "Must be true before submitting". If it did, GitHub would see an IP address, and the label would still be "not collected" (not retained by the developer), but the build would be rejected.

The privacy policy page (scripts/site/legal.py, rebuilt with scripts/site/build.py) must change in the same commit.
