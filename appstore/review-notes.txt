================ PART 1: PASTE FROM THE NEXT LINE TO THE LINE "END OF PART 1" ================
IPTVMac is a media player for the user's own IPTV sources (M3U playlist links and Xtream Codes logins). It contains and provides NO content, channels or subscriptions, and it has no account or login of its own. Until a source is added the lists are empty, by design. We are not an IPTV provider.

HOW TO TEST (about 2 minutes, no demo account needed)
1. On first launch the welcome guide opens. Click Next.
2. Choose the "M3U" segment. Name: Review. Playlist link: https://goelir.github.io/IPTVMac/review/ReviewPlaylist.m3u then click Next.
3. Click "Test connection" ("Connected successfully"), then "Save and sync".
The playlist holds only open-licence films by the Blender Foundation (Big Buck Bunny, Sintel, Tears of Steel, Elephants Dream; Creative Commons Attribution) on public servers: 10 entries, 2 under Live, 5 under Movies, 3 under Series.
Try: tab Live > "Big Buck Bunny (HLS stream)". Tab Movies > click "Sintel Trailer (2010)": built-in player, [ and ] change speed, the Picture in Picture button floats the video. The Search field. Right-click a movie > "Add to favorites" or "Download"; the toolbar download button opens Downloads. More sources: Settings > Playlists > "Add source...".

THINGS YOU MAY ASK ABOUT
- Downloads: the user can save a movie from their OWN source to a folder they choose (first use shows a standard folder panel). It saves the exact stream the user's provider serves to that user. The app downloads nothing from other services (not YouTube, not any site) and converts nothing. Try "Sintel Trailer (2010)" (7 MB).
- Xtream Codes: the other source type (Server address, Username, Password). It needs a provider account we cannot supply, because the app has no service of its own. The M3U path above uses the same playback, search, favorites and download code.
- DRM: the app has no code to bypass copy protection. DRM-protected streams (FairPlay, Widevine, PlayReady) do not play.
- Trailer (title details): hands a YouTube link to the user's web browser; nothing plays or is saved in the app.
- Network: the app connects only to servers the user enters and to the logo and stream addresses those sources return. No developer server, no analytics, no ads, no tracking, no account. Privacy policy: https://goelir.github.io/IPTVMac/privacy/
- ATS: Info.plist sets NSAllowsArbitraryLoads because IPTV providers commonly serve plain http://host:port addresses (often an IP address) that the user types in and that we cannot list in advance. The app makes no connection on its own.
- Mac App Store requirements (2.4.5): App Sandbox with outgoing connections and user-selected files (download folder, backup export and import). No updater: updates come only from the Mac App Store. No license screen. One self-contained bundle (libmpv and FFmpeg, LGPL builds, bundled). No code is downloaded or executed.
- Age rating: the app itself has no mature material; because users can add any source, we set the rating by override to 18+.
Support: https://goelir.github.io/IPTVMac/support/

LIKELY REJECTIONS FOR AN IPTV PLAYER AND THE ANSWERS
(guideline numbers are from the text read at developer.apple.com/app-store/review/guidelines on 2026-10-11, "Last Updated: June 8, 2026")

5.2.1 / 5.2.2 "Your app facilitates access to copyrighted content / third-party services" ->
  The app is a general-purpose player, not a service. No catalogue, no default source, no provider list, no recommended playlists in the app; the user supplies the source and must be authorized to use it (said in the description, on the website, on the support page). The developer has no relationship with any provider. Same position as any media player that opens a user-supplied address. Attach: content-rights.txt facts, the repository link, the review playlist.
5.2.3 "The app can save or download media from third-party sources" ->
  Downloads saves the stream a user's own provider serves to that user, into a folder the user picks. It never contacts YouTube, Vimeo or any public video site, and it does not convert. If the reviewer insists, offer to remove Downloads from the App Store build (the direct-download build keeps it).
2.1 "We could not find content / app showed an empty screen / need a demo account" ->
  Empty until a source is added, by design. No account exists, so there is nothing to log into. Steps and a self-contained open-licence playlist are in the notes. Offer a screen recording of the three steps if they cannot reach the URL.
2.1 (a) "URL does not work / placeholder" -> Support https://goelir.github.io/IPTVMac/support/ and privacy https://goelir.github.io/IPTVMac/privacy/ must return 200 on submission day (they exist only after the branch is merged and deployed).
1.5 / App Store Connect "Support URL must lead to actual contact information" -> see CHECKLIST.md: set CONTACT_EMAIL in scripts/site/build.py and rebuild.
2.3.x "Metadata does not match / mentions content" -> the description says plainly that there is no content and that a source is required; keywords carry no brand, price or platform words (appstore/check-listing.py checks this).
2.3.6 "Age rating inaccurate" -> see age-rating.txt: literal answers plus the 18+ override. The reply: "The app contains no mature content; since it plays whatever source the user adds, we rated it 18+."
4.2 "Minimum functionality / repackaged website" -> native macOS app (SwiftUI + libmpv): local SQLite full-text search over 100,000+ items, built-in player with speed 0.25x to 4x, subtitles, Picture in Picture window across Spaces, catch-up, downloads, backup and restore, 31 languages incl. right-to-left.
4.3 (b) "Indistinguishable from other IPTV players" -> state the differences: native app, instant local search, own Picture in Picture, no account, no ads, no analytics, open source (https://github.com/Goelir/IPTVMac). One bundle ID, no variants (4.3 (a)).
4.1 (c) "Name or icon" -> the name IPTVMac and the icon (scripts/icon/icon.swift) are the owner's; no other product's name or logo is used.
5.1.1 (i) "Privacy policy / link in app" -> policy URL in App Store Connect; in-app link must exist (open item in CHECKLIST.md).
2.4.5 "Mac App Store requirements" -> (i) sandboxed, (ii) Xcode packaging, self-contained bundle, (iii) no launch at login, no helper left running, (iv) downloads no code, (vii) no other updater, (ix) all 31 localizations are in the one bundle. Each must be true in the submitted build: CHECKLIST.md.
2.5.5 "Not functional on IPv6-only networks" (guideline text read; not something I tested) -> hostnames work through NAT64. Providers that give a literal IPv4 address in http://1.2.3.4:8080 may not be reachable from an IPv6-only network; that is the provider's address, not the app's.
1.2 "User-generated content" -> none: no posting, sharing, profiles or chat.
3.x payments -> none: free, no in-app purchase, no subscription, no external payment link.
ATS question ("NSAllowsArbitraryLoads") -> the sentence in Part 1. If asked to narrow it: NSAllowsArbitraryLoads cannot be replaced by a domain list because the domains are the user's; NSAllowsLocalNetworking alone would break providers on the internet.
