# iOS resources (`ios/Resources`)

Everything the iPhone/iPad app needs that is not code: asset catalog, privacy manifest, Info.plist keys, per-language `InfoPlist.strings`, acknowledgements.
Checked by `scripts/ios-assets-check.sh` (read-only, safe to run any time). Written 2026-10-11 against Xcode 27.0, the libmpv build media-kit `v0.7.3` and GRDB 7.11.1.

## Files

|---|---|---|
| `Assets.xcassets` | `AppIcon` (one 1024x1024 universal iOS icon, opaque, full bleed, no rounded corners), `AccentColor` (#6F59E6, the logo violet), `AccentText` (violet for text/glyphs, 5B3DE0 light / A496FF dark), `LaunchBackground` (#0B0D14), `PosterPlaceholder` (E6E6F0 light / 26283A dark), `LogoMark` (TV glyph, 160 pt, 1x/2x/3x, transparent) | Copy Bundle Resources of the app target. Check results (Xcode 27.0): `plutil -lint` OK on 33 files; `actool --compile ... --platform iphoneos --minimum-deployment-target 17.0 --app-icon AppIcon --accent-color AccentColor` exit 0, no warnings, produces `Assets.car` (AppIcon, AccentColor, 4 more sets) and the partial Info.plist (`CFBundleIconName`, `NSAccentColorName`); icon 1024x1024 RGB without alpha.

## `PrivacyInfo.xcprivacy`

`NSPrivacyTracking` false, no tracking domains, `NSPrivacyCollectedDataTypes` empty.
**Why "collects nothing" holds (verified by reading `Sources/**`)**: no analytics, crash, advertising or identifier code (grep for analytics/telemetry/crashlytics/sentry/firebase/identifierForVendor/IDFA: none). Network traffic goes to hosts the user typed (Xtream API, M3U, EPG, streams, `tvg-logo` images) via URLSession and libmpv. Two other destinations exist in the shared code: the GitHub updater (`IPTVCore/Updater.swift`, `api.github.com`) and a YouTube trailer link (`ItemInfo`, opened outside the app). **The iOS target must not call `Updater.check`** (an iOS app cannot self-update anyway); if it ever does, GitHub sees the IP address and "Data Not Collected" needs a second look. Passwords stay in the local database (`SecretStore`), nothing leaves the device except to the user's own provider. App Store Connect label: "Data Not Collected".

### Required-reason APIs

Reason list read 2026-10-11 (fetched as JSON from developer.apple.com): https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api (the URL in the task, `.../privacy-manifest-files/describing-use-of-required-reason-api`, now returns 404; the page moved one level up) and its children `NSPrivacyAccessedAPIType`, `NSPrivacyAccessedAPITypeReasons`.

| Category | Reason | Meaning (Apple) | Evidence | Status |
|---|---|---|---|---|
| FileTimestamp | `C617.1` | metadata of files inside the app container | `stat`/`fstat`/`lstat` imported by Mpv, Avformat, Avutil, Harfbuzz, Mbedx509 (CA file), Xml2 (`nm -u` on the iOS arm64 slices of v0.7.3); `FileManager.attributesOfItem` in `IPTVCore/Backup.swift` | symbols verified; which paths they touch at run time assumed |
| FileTimestamp | `3B52.1` | files the user granted access to (document picker) | playlists, subtitles, backups the user picks in Files or "Open in" | assumed from the planned features |
| SystemBootTime | `35F9.1` | elapsed time between events, timers | `mach_absolute_time` in Mpv (`osdep/timer-darwin.c` at `v0.36.0` includes `mach/mach_time.h`: mpv's monotonic clock); `ProcessInfo.systemUptime` in `IPTVPlayer/SeekPreviewer.swift` (throttle timer, read) | symbol and source verified |
| DiskSpace | `E174.1` | check there is enough space to write files | `fstatfs` imported by Mpv. mpv calls it only to read the filesystem type (`stream/stream_file.c` at `v0.36.0`, `check_stream_network`: `fstatfs` then `strcmp` of `f_fstypename` against `afpfs`, `nfs`, `smbfs`, `webdav`, ...; the strings are in the binary), never free space. **No listed reason describes that; `E174.1` is the closest and what Yattee (mpv, App Store) ships (its manifest, read from GitHub).** | symbol verified; **reason fit ASSUMED**. Alternatives: ask Apple for a new reason (https://developer.apple.com/contact/request/privacy-manifest-reason/), or add a real free-space check before writing a file |
| UserDefaults | `CA92.1` | data only the app itself can access | `UserDefaults.standard`, `@AppStorage` in the app layer (about 25 keys). `AppPrefs` writes `AppleLanguages` into the app's own domain, which the system also reads; if review objects, drop the in-app language switch (iOS 16+ has per-app language in Settings) | verified |

Not declared, checked absent: ActiveKeyboards (`activeInputModes` appears nowhere), `volumeAvailableCapacity*` (only in the macOS-only `Downloads.swift`; v1 ships without Downloads, guideline 5.2.3). `sysctl`/`sysctlbyname` (Avutil, Dav1d: `hw.logicalcpu`), `gettimeofday` are not on Apple's list.
Not included: `DDA9.1` (we show no file timestamps), `0A2A.1`/`C56D.1` (SDK-only).
New Swift code can add APIs: `scripts/ios-assets-check.py` greps `Sources/**` and `ios/**` for the five categories and fails when one is used but not declared. A hit in a macOS-only file is a hint, not proof.

### Third-party SDK manifests

Apple's list of commonly used SDKs that must ship their own manifest and signature (https://developer.apple.com/support/third-party-SDK-requirements/, read 2026-10-11) has 86 entries, among them BoringSSL, OpenSSL, FMDB, SDWebImage. **It contains none of mpv/libmpv, FFmpeg, mbedTLS, dav1d, libass, harfbuzz, freetype, fribidi, libxml2, uchardet, libpng or GRDB, and mbedTLS is not a repackaging of OpenSSL, so the requirement does not apply.** GRDB ships its own manifest anyway (`GRDB/PrivacyInfo.xcprivacy` in 7.11.1: no tracking, no APIs).
Caveat (Apple's wording, same page as above): "For each executable or dynamic library in an app that uses a required reason API, the bundle that includes it needs to include a privacy manifest file that reports the API". The 18 mpv frameworks are binary xcframeworks without manifests (media-kit's own Flutter wrappers ship empty ones). Declaring the union in the app manifest is what other mpv apps do (Yattee) and what the upload check reads, but I could not test an upload. **If App Store Connect answers with ITMS-91053 for a framework, copy this file into the embedded frameworks** (`$FRAMEWORKS/Mpv.framework/PrivacyInfo.xcprivacy`, a build phase before code signing) and re-upload.

## `Info-extra.plist`: decisions

- `UILaunchScreen`: dark `LaunchBackground` colour plus `LogoMark`, no storyboard.
- `UIRequiredDeviceCapabilities` `arm64`; orientations: portrait + both landscapes on iPhone, all four on iPad; `UIBackgroundModes` `audio` (guideline 2.5.4; Picture in Picture also needs it).
- **`NSLocalNetworkUsageDescription`: when iOS asks.** The first time the app opens a connection (URLSession or libmpv's own sockets) to a private or link-local address: 192.168.x.x, 10.x.x.x, 172.16-31.x.x, 169.254.x.x, `*.local`. Public hosts never trigger it. It asks once; the choice lives in Settings > IPTVMac > Local Network. If denied, LAN sources fail to connect (the app should say why and point to that setting). Text: "IPTVMac connects to playlists and streams on your home network, such as an IPTV box or a media server. It only contacts the addresses you add yourself and never scans your network." Translations in the 31 `InfoPlist.strings` are AI-assisted (no native review; have speakers read ar, bn, fa, ur, hi, th, sq before release).
- **`NSBonjourServices`: deliberately absent.** It is only needed to browse Bonjour services, and the app does not (users type the address); the local-network prompt for direct connections needs the usage string alone. Add `<key>NSBonjourServices</key><array><string>_hdhomerun._tcp</string></array>` (or whatever type) together with the discovery code if that feature comes. `ios-assets-check.py` fails while the key is present, so adding it means editing that check on purpose.
- **`UIFileSharingEnabled`: no.** It would expose the app's Documents folder in Files and Finder; the app keeps its data in Application Support and v1 has no Downloads.
- **`LSSupportsOpeningDocumentsInPlace`: no.** Playlists and subtitles are small and imported once; the default copy-in gives the app its own file (no security-scoped bookmarks to keep alive). `fileImporter` in the app needs no plist key. If in-place is wanted later, the app must call `startAccessingSecurityScopedResource` and store bookmarks.
- `NSAppTransportSecurity` / `NSAllowsArbitraryLoads`: as on macOS, IPTV panels are mostly plain http. Only the Xtream API calls (URLSession) are subject to ATS; libmpv's sockets are not. Say that in the review notes.
- **`ITSAppUsesNonExemptEncryption` = false is the value the task asked for, but it is an OWNER DECISION.** Apple (https://developer.apple.com/documentation/security/complying-with-encryption-export-regulations): NO if the app, "including any third-party libraries it links against", uses no encryption or only exempt forms; OS-provided HTTPS via URLSession is exempt. Apple's table (App Store Connect help, "Export compliance documentation for encryption"): "an industry standard algorithm, not provided within the Apple operating system" needs the French encryption declaration (only if distributed in France). mbedTLS inside libmpv is exactly that, so NO is right only if the owner concludes it is exempt; otherwise set `true` and answer the questions in App Store Connect once (and see the annual self-classification report note in the Security page). Excluding France from availability avoids the French form.
- Document types: `public.m3u-playlist` (the system type of both `.m3u` and `.m3u8`, checked with `UTType(filenameExtension:)` on macOS 27; iOS shares the type, not run on iOS) and, for subtitles, `io.github.goelir.iptvmac.subrip|ass|ssa` imported here (no system type exists for srt/ass/ssa) plus the system `org.w3.webvtt`. Role Viewer, rank Alternate (offered in "Open in", never the default). Limit: if another installed app maps `.srt` to its own UTI the file may not be offered to us. The app must handle `onOpenURL`: playlist: copy to Application Support and import (the M3U parser must read a local file; the existing account kind is URL-based); subtitle: `MPVPlayer.addSubtitle(url)` during playback, otherwise say "open a video first". The copy lives in the Inbox: copy before use, it can be deleted by the system.

**Owner decisions and gaps**
1. The "relinking" paragraph promises that the owner will provide anything needed to relink with a modified library (contact: GitHub issues). Confirm the promise, or give a contact address. The open legal question from the feasibility report remains: LGPL-3.0 "Installation Information" on a locked-down iPhone with FFmpeg built `--enable-version3`; counsel needed. The in-app text states the facts and takes no position.
2. App Store terms for IPTVMac's own code are not discussed in the in-app text (it only says the source is GPL-3.0 on GitHub). Add a sentence there if the owner offers the App Store build under other terms.
3. **The Mozilla CA bundle entry assumes the app bundles `cacert.pem`.** libmpv's mbedTLS has no system trust store on iOS (`tls-ca-file=/etc/ssl/cert.pem` does not exist), so a bundle must ship. It is not part of this folder: whoever adds it (curl.se/ca/cacert.pem) keeps the entry; if not bundled, delete the entry and the matching check is not enforced.
4. README says the macOS bundle is a "GPL build"; the binaries say LGPL-3.0+ (same v0.7.3 flavour). Fix the README sentence (outside this folder).

## What the ios-app agent / owner must wire

1. Add `Assets.xcassets`, `PrivacyInfo.xcprivacy`, the 31 `InfoPlist.strings` and `Acknowledgements.txt` as target resources; set `INFOPLIST_FILE`, `GENERATE_INFOPLIST_FILE`, the two asset-catalog build settings; `knownRegions` = the 31 codes; exclude `Acknowledgements.md` and `Info-extra.plist` from resources.
2. Settings > About: show `Acknowledgements.txt`; also link the privacy policy URL (guideline 5.1.1) next to it.
3. `onOpenURL` for the document types above; do not call `Updater.check`.
4. Ship a CA bundle and set `tls-ca-file` to it (see gap 3).
5. Decide the export-compliance key and the LGPL points (owner); native-review the translations.
6. Run `scripts/ios-assets-check.sh` in CI or before each upload; run `scripts/ios-assets-gen.sh` only if the artwork changes (iOS 18 dark/tinted icon variants are not provided: the single universal icon is used for all appearances).
7. After the first App Store Connect upload read the validation e-mail: it is the only authority on the reason codes (ITMS-91053/91056).
